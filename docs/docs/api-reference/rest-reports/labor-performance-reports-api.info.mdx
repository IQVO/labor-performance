The READ-ONLY analytical surface of the Labor Performance bounded context's data product (ADR 0007), served by the separate `cmd/labor-reports` binary over a read-only pool against the analytical database — NOT by the OLTP `cmd/labor` binary documented in apis/openapi.yaml.
The report is a projection over this service's own domain events (LaborStandardDefined, LaborStandardRevised, TaskPerformanceRecorded), delivered on the `warehouse.labor-performance.analytics` topic and applied by `cmd/labor-projector` — the single writer. It is therefore EVENTUALLY CONSISTENT: use GET /reports/performance/freshness to see how far behind the event stream the read model currently is.
Every mean in this API is NULLABLE, and null is a real answer that clients must handle distinctly from zero. An hour bucket can hold real, counted tasks and still have no efficiency number — because no engineered standard was active at completion time, or because the completion carried no measurable duration. Reporting 0 in that case would brand an unmeasurable hour as a 0%-efficient one, which this context refuses to do (ADR 0004).
